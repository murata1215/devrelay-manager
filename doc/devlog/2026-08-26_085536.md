## 発見

①**留保3の前提が公式一次情報により否定された**: `claude-opus-5`/`claude-sonnet-5`は「将来差し替わる別名」ではなく、公式記述「Every Claude model ID is a pinned snapshot, including the dateless IDs used from the 4.6 generation on.」の通り**それ自体がpinned snapshot**。日付付きIDは4.6世代以降には公式に存在しないため、日付を捏造せず現行IDのまま`idForm:'pinned-dateless'`として記録するのが正しい対応と判断した。②`DISPATCH_WORKER_MODE==='off'`でも検証すると決めた根拠: (a) `config/manager-settings.json`はコミットされた成果物で環境非依存のため、モードで検証有無が変わると「offの開発機では起動できたのにresidentの本番で初めて落ちる」という乖離が生じる、(b) governanceテンプレの欠落は人間ゲートに提示される安全文言の欠落に直結し検出は最速・一様であるべき、(c) 起動時1回の同期ファイル読み取りのみでコストは無視できる。③AST採用の理由: 正規表現の継ぎ足しはコメント・文字列リテラル・複数行importで誤検出/検出漏れの温床になり続ける。`typescript`は既存devDependencyかつテストは本番ビルド対象外（tsconfig.jsonのexclude）のため新規依存ゼロで導入できた。④design doc §12のopen item（`classifyBuildResult`のfailed/unknown語彙、building 120分バジェット）は本サイクルでも未解消のまま（実機検証が必要なため非スコープ）。
