# 2026-09-05 18:19 JST ｜ サイクル1.34: DISPATCH_WORKER_MODE の恒久化

## 要求

`DISPATCH_WORKER_MODE=resident` は現在 PM2 の env スナップショット
（`~/.pm2/dump.pm2`）にしか存在せず、`apps/server/.env` にもリポジトリにも
記述が無かった（サイクル1.32 の調査で判明）。`parseWorkerMode`
（`apps/server/src/orchestrator/dispatch-worker.ts:477-485`）は未設定・空文字を
throw せずサイレントに `'off'` へ倒すため、PM2 を登録し直すと警告も例外も無く
`orchestratorRoutes`/`dispatchRoutes` が未登録になり、web からの送信が全て
404 になる（添付があると 1.29 の `canFallbackToMessageOnly` により Message 行も
作られずエラー表示のみになる）。このリスクを解消するため `.env` に恒久化する。

本サイクルは `.env` への `DISPATCH_WORKER_MODE` 追記のみを対象とし、
ソースコード・DB・PM2 設定には一切触れない。

## 事前確認（変更前に実施・両方クリアしたため実施に進んだ）

### ① `.env` が実際に起動時に読み込まれることの確認

- `apps/server/src/index.ts:1` の `import 'dotenv/config';` が起点。
- `dotenv@16.6.1` の `config.js` は `lib/main.js` の `config()` を呼び、
  既定パスは `lib/main.js:212` `path.resolve(process.cwd(), '.env')`。
- 稼働中プロセス（PID 2939673）の cwd を実測: `ls -l /proc/2939673/cwd` →
  `/home/keisuke/devrelay-manager/apps/server`。つまり dotenv が読むのは
  まさに編集対象の `apps/server/.env`。
- 傍証: `.env:15` の `PORT=9026`（PM2 env には存在しない）が実際に効いている
  （起動ログ `Server listening at http://0.0.0.0:9026`。未設定時の既定は
  `index.ts:185` により `3100`）。

### ② dotenv が既存 env を上書きしないことの確認

- `dotenv/lib/main.js:338-365` の `populate()`:
  `override` 既定 `false` → `Object.prototype.hasOwnProperty.call(processEnv, key)`
  が真の場合は代入をスキップする。
- `override` を外から立てられるのは `DOTENV_CONFIG_OVERRIDE` 環境変数のみだが、
  稼働中プロセスの environ に `DOTENV_CONFIG_*` は **0件**
  （`tr '\0' '\n' < /proc/2939673/environ | grep -c "DOTENV_CONFIG"` → `0`）。
- ⇒ PM2 が注入した `DISPATCH_WORKER_MODE=resident` が常に勝ち、
  `.env` への追記は**現時点の挙動を一切変えない**（同値でもあるため二重の意味で無害）。

両条件が確認できたため、`.env` の変更を実施した。

## 実行

`apps/server/.env` の末尾に以下の1行のみを追記した（既存17行は無改変）。

```
DISPATCH_WORKER_MODE=resident
```

`.env.example` を含む他のファイルは一切変更していない。

## 発見・判断

- **なぜ恒久化が必要だったか**: `resident` は `~/.pm2/dump.pm2` の env
  スナップショットのみに存在するため、`pm2 kill && pm2 start` 等で
  PM2 のプロセス管理を再登録すると、そのスナップショットが失われる。
  `parseWorkerMode` は未設定を例外にせず `'off'` へ倒すため、この再登録が
  **警告なしに** manager の中核機能（dispatch ルート自体の登録）を止める
  リスクがあった。`.env` に書いておけば、PM2 env に当該キーが無くなっても
  dotenv がフォールバックとして供給する。
- **現時点で挙動が変わらない理由**: dotenv は `override: false` が既定であり、
  既に `process.env.DISPATCH_WORKER_MODE` が PM2 から注入されているため、
  `.env` の値は**今は使われない**（無視される）。効果が現れるのは
  **次に PM2 のプロセスを再登録し、PM2 env のスナップショットから
  `DISPATCH_WORKER_MODE` が失われたとき**であり、そのときに初めて `.env` の
  `resident` がフォールバックとして採用される。
- `.env` は `.gitignore:3` で追跡対象外のため、この恒久化は
  **本マシン（x220-158-18-103 / keisuke ユーザーの実行環境）限定**である。
  別マシンへ複製・再構築する場合は、そちらでも `.env` に
  `DISPATCH_WORKER_MODE=resident`（または用途に応じた値）を用意する必要がある。
