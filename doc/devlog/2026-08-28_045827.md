# 2026-08-28 04:58 JST ｜ サイクル1.15: ゲート①の governance 再検証

## 要求
1.14 の発見①：ゲート①（`approve-target`）は body の `instruction` を governance 再検証なしでそのまま Dispatch 行に書き戻していた。人間操作画面は任意文字列を送れるため、governance テンプレを剥がした文面でも通せる余地が構造として残っていた。まず `composeInstruction` が冪等かを確認し（前提）、冪等でなければ冪等化した上で、ゲート①経路に draft 生成時と同じ `composeInstruction`/`assertGovernanceApplied` を再適用する。人間による本文の書き換え自体は許可のまま、governance 句が欠けた状態での保存だけを禁止する。空文字・空白のみの instruction は 400・無遷移とする。

## 実行
`composeInstruction`（`governance.ts`）は `header + body + footer` の単純連結のみで、実際に冪等ではないことをコードレビューで確認した（2回適用すると `H+H+body+F+F` に二重化する）。そこで `stripGovernanceTemplate`（既存の header 接頭辞・footer 接尾辞を剥がす純粋関数。header/footer が空文字のときは無限ループガードあり）を新設し、`composeInstruction` を「strip → 空チェック → 連結」に変更して冪等化した。`dispatch-gates.ts` の `approveTarget` を①空チェック（core 未呼び出し・無遷移）→②freshCheck→③`composeInstruction`+`assertGovernanceApplied`（draft 生成時と同じ2関数・同じ並び）→④`transitionDispatch`、の順に変更し、`ApproveTargetDeps`（`GateDeps` 拡張、`settings` 追加）と `ApproveTargetResult`（`code: 'empty_instruction' | 'fresh_check'` 追加）、HTTP 写像用の純粋関数 `approveTargetHttpStatus` を新設した。`GateDeps` 自体は変更せず、`approvePlan`/`retryStale`/`cancelDispatch` は無改変。`routes/dispatch.ts` のゲート①ルートのみ `readManagerSettingsFile()` を注入し `approveTargetHttpStatus` で 200/400/409 を分岐するよう変更した。
