# 2026-08-28 05:43 JST ｜ サイクル1.16: スレッド別 Dispatch 一覧 API

## 要求

次サイクル1.17（フロント `apps/web`）でスレッドのタイムラインに Dispatch を per-repo バッジ付きで並べるための下ごしらえとして、`GET /threads/:threadId/dispatches` を追加する。既存は `GET /dispatch/:id` の単体取得しか無く、スレッド単位で Dispatch をまとめて取る経路が欠けていた。フロント本体は本サイクルの範囲外。

## 実行

新規 `orchestrator/dispatch-view.ts`（import ゼロ・純粋）に `serializeDispatch`（ホワイトリスト整形）と `listThreadDispatches`（スレッド存在確認 → Dispatch 一覧取得）、`listThreadDispatchesHttpStatus` を実装。`dispatch-store.ts` の既存型（`DispatchListRow`/`DispatchQueryClient`）は列数不足・シグネチャ不一致（`findMany` が worker 専用の `take` 必須形）のため再利用せず、新規の narrow なインターフェース（`ThreadReadClient`/`ThreadDispatchListClient`）を別建てにした。`routes/dispatch.ts` に新ルートを追加し、既存の `GET /dispatch/:id` も同じ `serializeDispatch` 経由に変更（レスポンス形式は不変）。

## 検証

`pnpm typecheck`（`tsc --noEmit` ×2）0エラー。`pnpm test` は新規8件（#129〜#136）を含め **136/136 pass・fail 0**（従来128件は無変更で全緑）。#99（LLM層の推移閉包・禁止フラグメント7点）もグリーン維持を確認。サーバー起動・実API呼び出しは行っていない。

## 発見

1. `Dispatch` モデルに `deletedAt` 列が無い（`Thread` にしか無い）ため、要求どおりの「Dispatch の deletedAt が null のものだけ返す」は現スキーマでは実装不能。soft-delete 除外は Thread 側（`thread.deletedAt != null` → 404）に落とし、生きているスレッドの Dispatch は全件返す設計にした。
2. plan 本文（core 側が権威）を保持する列は Dispatch に存在しないため、要求の但し書きどおりレスポンスから除外した。
3. 共有シリアライザが未実装（grep 0件）だったため新規作成。ホワイトリストは要求17列ではなく `schema.prisma` の Dispatch スカラー列20列全部にした。理由は、要求列だけに絞ると現行 `/dispatch/:id` が返している `statusChangedAt`/`statusReason`/`lastPolledAt` の3列が消え「既存レスポンス形式を変えない」制約に反するため。新設した #135 でスキーマとシリアライザ出力キーの完全一致を機械検証し、将来の列追加時に silent な欠落が起きないようにした。
