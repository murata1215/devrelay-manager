# 2026-08-28 18:30 JST ｜ サイクル1.18: apps/web 最小 SPA

要求: `doc/web-manager-surface-concept.md` §3・§9 の v1 レイアウトを、manager API のみを叩く最小 SPA として実装する。`apps/server` には一切触らず、1.16/1.17 で用意した `GET /threads/:threadId/dispatches` / `GET /dispatch/:id/plan` を使い切ること。

実行: `apps/web`（`@devrelay-manager/web`）を新規ワークスペースとして追加。Vite 7 + React 19 + TypeScript のみ（依存はルーター・状態管理・UI ライブラリ・Markdown レンダラ無しの指定どおり、検証用に `tsx`/`@types/node` のみ追加）。左=スレ一覧＋新規作成、右上=タイムライン（`src/lib/timeline.ts` で messages と dispatches を createdAt 昇順に結合）、右下=入力欄＋council トグル（disabled）、下部=プロジェクト複数選択（ヒント表示のみ）、上部=app 切替リンク。Dispatch カードは状態別に draft（instruction 編集＋ゲート①）／awaiting_approval（展開時に plan 取得＋ゲート②）／stale（再取得）／done（トークン等の表示）を分岐し、非終端状態には中止ボタンを出す。承認・中止は `window.confirm` を挟み busy 中は disabled。選択中スレに非終端 Dispatch が1件でもあれば4秒間隔でポーリング、無ければ止める。19 ファイル（うちテスト3本）＋ルート package.json に `dev:web`/`build:web` を追加。

検証: `apps/web` で `pnpm test`（`node --import tsx --test`、server と同方式）14件全 pass、`pnpm typecheck`（`tsc --noEmit`）エラー無し、`pnpm build`（`vite build`）成功（`dist` 220K、JS 206.56kB/gzip 65.31kB・CSS 3.66kB/gzip 1.14kB）。`apps/server` 側は `pnpm test` 146件・`pnpm typecheck` とも不変を確認、`git status` で `apps/server` 配下に差分が無いことも確認。実サーバー・ブラウザは起動していない。

発見: (1) `POST /threads/:id/orchestrate` が内部で user Message 行を自作成する（`orchestrator.ts:110`）ため、指示どおり「messages→orchestrate」の順で叩くと user 発言が二重登録される。orchestrate 単発呼び出しに変更し、404（`DISPATCH_WORKER_MODE=off`）のときだけ `POST /messages` へフォールバックする設計にした。(2) orchestrate の body は `{content, tier?, intent?}` のみでプロジェクト選択を渡す口が無い（サーバー内部で `coreClient.listProjects()` を引いて LLM に渡す設計）。下部のプロジェクト選択は UI 上のヒント表示に留まり実際の送信には使われない — orchestrate にプロジェクト選択を受け渡す拡張余地がサーバー側に見つからなかった。(3) `POST /dispatch/:id/approve-target` は `{instruction}` のみ受理し projectId は DB 行から取るため、draft カードの「投げ先変更」select は disabled にせざるを得なかった。(4) `POST /threads` が `ownerId` 必須（認証未実装）のため `VITE_OWNER_ID`（既定 `web-local`）で固定した。
