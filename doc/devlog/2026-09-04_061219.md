# 2026-09-04 15:12 JST ｜ サイクル1.24: 会話返答の永続化バグ修正

## 要求
1.24-pre の調査で確定した不具合の修正。web から会話的発話（例「こんにちは」）を送っても `POST /threads/:id/orchestrate` は 200 を返すのに `Message(role='manager')` が DB に作られず、タイムラインに manager の返答が表示されなかった。LLM 層（`orchestrator-llm.ts`）は db import 禁止の構造テストがあるため、永続化はルート層（`routes/orchestrator.ts`）で行う方針で実装した。

## 実行
- `orchestrator/conversation-reply.ts`（新規）: `orchestrate()` の結果から保存すべき manager Message 本文を返す純粋関数 `managerReplyContent`。`conversation` → reply をそのまま、`invalid` → 定型文＋issues 箇条書き（無言 200 の解消）、`proposal` → null（Dispatch カードと二重表示させない）
- `routes/orchestrator.ts`（編集）: `orchestrate()` 直後に `managerReplyContent` を呼び、非 null なら `prisma.message.create({ role:'manager', ... })`。tier/model は `OrchestrateResult` に含まれないため、`orchestrate()` 内部と同一の入力（intent/tierOverride/settings）でルート側が `resolveTier`/`resolveModel` を再計算して記録。レスポンス body の形式（`{ messageId, result }`）は不変
- `conversation-reply.test.ts`（新規）: conversation/proposal/invalid（issues 有無2パターン）の4ケース、#166〜#169
- 実装前に `orchestrator-llm-structure.test.ts` の `ENTRY_FILES`（5ファイル固定・orchestrator-llm.ts から出ていく import を辿る方向）を確認し、新規ファイルは逆向き参照のため閉包に入らないことを検証してから着手した
